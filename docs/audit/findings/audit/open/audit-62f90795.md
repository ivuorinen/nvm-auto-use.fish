# command -q fd accepts a broken shim, silently reporting zero files

## Problem

`_nvm_cache_stats` and three sites in `nvm_doctor` probe for `fd` with
`command -q fd` and, on success, trust its output. A version-manager shim
(mise, asdf) satisfies `command -q` because the shim binary is on PATH, but
running it can fail — printing an error to stderr and nothing to stdout. The
count then reads as 0 with no indication anything went wrong.

## Evidence

`functions/nvm_cache.fish:101-105`:

    if command -q fd
        echo "Cache files: "(count (fd --type f . "$cache_dir" 2>/dev/null))
    else
        echo "Cache files: "(count (find "$cache_dir" -type f 2>/dev/null))
    end

Reproduced on a host where `fd` is a mise shim with no version selected
(exercised accidentally while isolating XDG_CONFIG_HOME in the test harness):

    $ fd --type f . "$cache_dir"
    mise ERROR No version is set for shim: fd
    $ echo $status
    0-output, no stdout

With two files present in the cache directory:

    fd count   = 0
    find count = 2
    du -sh     = 12K

`nvm_cache stats` reported `Cache files: 0` alongside `Cache size: 12K` — two
lines of the same output contradicting each other.

The `2>/dev/null` on the `fd` call suppresses the shim's error, so nothing
surfaces to the user.

## Impact

`nvm_cache stats` and `nvm_doctor` report an empty cache on any host where
`fd` is an unresolved shim. `nvm_doctor` is the command users run when
something is already wrong; it hands them a false "cache is empty" reading and
sends them down the wrong path. Same pattern at `nvm_doctor.fish:207`, `:299`,
`:349`.

## Fix

Do not treat `command -q` as proof the tool works. Capture the result and fall
back when it is empty:

    set -l files
    if command -q fd
        set files (fd --type f . "$cache_dir" 2>/dev/null)
    end
    if test (count $files) -eq 0
        set files (find "$cache_dir" -type f 2>/dev/null)
    end
    echo "Cache files: "(count $files)

Apply the same shape to the three `nvm_doctor` sites. Alternatively drop `fd`
entirely — `find` is already the fallback, is always present, and this is not
a hot path.
